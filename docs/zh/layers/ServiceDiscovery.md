# 服务发现

服务发现层把人类可读的名字映射到链上地址与内容，对标 DNS 的解析、授权与 TTL，但用密码学证明所有权。它回答一个问题——**这个名字现在归谁、指向什么**。

## 定义

服务发现层 = 命名系统 + 解析记录 + 所有权证明。

- **命名系统**：把 `0x4a8b...` 这样的地址换成 `alice.eth`。对标 DNS 的域名，但名字本身是链上资产。
- **解析记录**：记录类型对标 DNS 的 A/AAAA/CNAME/TXT。链上是 address、text、contenthash 等键值对。
- **所有权证明**：名字是 token 或链上记录，转移即改所有权，不依赖中心化注册局。对标 DNSSEC 的签名验证，但用更直截了当的方式——链上状态本身就是证明。

服务发现层之上是用户与 dApp，之下是[结算层](/zh/layers/Settlement)（记录必须被结算才不可变）与[存储层](/zh/layers/Storage)（contenthash 指向的内容在哪）。

## 解决的问题

1. **地址可读性**：`0x` 长地址不可读、不可记。名字让交易对人与应用都能识别。
2. **所有权可验证**：DNS 的域名所有权由注册局判定，纠纷走 UDRP 等流程。链上名字的所有权是状态，转移即生效，可被任何人验证。
3. **抗审查解析**：DNS 记录可被注册局或根区持有者删除。链上记录一旦结算就无法被单点删除（但浏览器网关仍可能审查，见失败模式）。
4. **多链命名**：一个名字在不同链上指向不同资产（主网 ETH 地址、BSC 地址、内容哈希），需要跨链解析。
5. **内容寻址**：名字可解析到内容哈希，让用户直接指向数据而非 URL。

## 现有系统

| 系统 | 对标 DNS 的部分 | 特点 |
| --- | --- | --- |
| ENS（Ethereum Name Service） | DNS 根区 + 解析器 | `.eth`，记录类型丰富，跨链解析，治理与治理提案；ENSIP-10 与 DNSSEC 集成 |
| SNS（Solana Name Service） | 域名 + 记录 | `.sol`，与 Solana 账户模型对齐 |
| Unstoppable Domains | 注册局 | `.crypto`、`.nft` 等后缀，一次性付费终身持有 |
| Handshake | 去中心化根区 | TLD 拍卖，对标 DNS 根区的去中心化版 |
| Space ID | 域名 | `.bnb`，与 BNB Chain 对齐 |
| ICNS（Internet Computer Name Service） | 域名 | IC 域内的命名 |
| DID（去中心化身份） | 标识符 | `did:ethr` 等，身份层而非命名层，常与服务发现联动 |

## 失败模式

- **抢注与域名狙击**：注册窗口开放时机器人抢跑，热门名字被抢注或溢价转卖。与[计算层](/zh/layers/Compute)的 MEV 问题同源——排序权被谁控制。
- **租金过期抢注**：ENS 域名年费过期后进入可被抢注状态，原持有人若忘记续费会丢域名。对标 DNS 的过期流程，但链上版本没有宽限期与注册局兜底。
- **解析器劫持**：恶意解析器返回错误地址，或浏览器扩展替换解析结果。链上记录正确，但解析环节被劫持。
- **ccip-read 信任链**：跨链解析依赖网关或预言机的签名转发。解析器拿到的是「第二方转述」，信任链比链上记录长一截。
- **浏览器层 DNS 劫持照旧**：`.eth` 名字要走网关解析，网关可被墙、被劫持或被审查。链上记录不可篡改，但用户看到的地址是错的。
- **商标争议与治理攻击**：ENS root 多签与治理提案若被劫持，可改变整个命名系统的规则。对标 DNS 的 ICANN 治理，但攻击面从政策机构变成了合约多签与治理提案。
- **钓鱼与同形字**：unicode 同形字、相似拼写（`1` 与 `l`、`0` 与 `O`）让用户以为打对名字。链上名字系统对此无内建防御，要靠检查器与用户教育。
- **记录类型滥用**：把私钥、密钥指纹等敏感数据放进公开可解析的记录，链上记录永久可见。

服务发现的失败几乎都遵循同一模式：**链上记录没变，但解析环节被人替换**。读一个服务发现案例时，先问「记录存在哪一层、解析走哪条路、那条路上谁能拦截」。

## 对标 DNS 的一张表

| DNS | 服务发现 | 差异 |
| --- | --- | --- |
| 域名 | `.eth` 等链上名字 | 所有权是状态，转移即生效 |
| 注册局 | 链上注册合约 + 治理 | 无中心化机构，规则由治理决定 |
| 解析器 | 合约解析器 + 网关 | 解析可被劫持，链路比 DNS 多一跳 |
| DNSSEC | 链上状态本身即证明 | 不需要签名链，但需要验证链状态 |
| TTL | 无（记录即时生效） | 无缓存失效窗口，但也无缓冲 |
| 根区（IANA） | 链上 root 合约 / Handshake 根 | 去中心化版根区，但仍是单点合约 |

## 设计要点

- 名字是资产，解析器才是单点：链上注册保证所有权，解析环节（网关、DNS、钱包）是劫持主战场，逐跳都要可验。
- 对标 DNS 的三层拆开设计：注册（所有权）、解析（映射）、根（治理）——单点从机构换成合约，不等于消失。
- 防同形字要在注册层做：unicode 相似字符检查、确认流程、可信列表——事后补救全来不及。
- 跨链/链下解析会拉长信任链：ccip-read 式签名转发每加一跳就多一个可替换环节，验证锚点要在链上终结。
