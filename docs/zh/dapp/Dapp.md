# DApp 架构

DApp（去中心化应用）是「前端与合约通过钱包交互、状态在链上、索引器提供链下查询」的应用形态。本目录给出架构图、开发栈、安全事故、L1/L2 选型与典型案例。

## 四要素

- **在哪一层**：[计算层](/zh/layers/Compute) + [服务发现](/zh/layers/ServiceDiscovery) —— 合约执行在链上，名字解析走[服务发现](/zh/layers/ServiceDiscovery)
- **解决什么**：把应用逻辑（合约）与状态（账本）放在链上执行，前端只负责交互与展示，消除单点故障
- **解决得怎么样**：开发栈成熟（Solidity、Hardhat、Ethers.js），但前端体验仍受链上延迟与 Gas 费限制；索引器解决了链下查询，但引入了新的信任锚（索引器的数据源链上状态）
- **出处**：[Ethers.js 文档](https://docs.ethers.org)、[Hardhat 文档](https://hardhat.org)、[The Graph 文档](https://thegraph.com)、[Aave 文档](https://docs.aave.com)、[ENS 文档](https://docs.ens.domains)

## 架构图

DApp 的典型架构是「四层」：

```
┌─────────────────────────────────────────────────────────┐
│                    前端（Frontend）                       │
│   React / Vue / Next.js                                  │
│   通过 wagmi / ethers.js 调用钱包与链                     │
└────────────────────┬────────────────────────────────────┘
                     │ RPC / WebSocket
┌────────────────────▼────────────────────────────────────┐
│                    钱包（Wallet）                         │
│   MetaMask / WalletConnect / Brave Wallet                │
│   签名交易、提交到链                                      │
└────────────────────┬────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────┐
│                  链上合约（Contracts）                    │
│   Solidity → EVM / WASM                                  │
│   状态存储在链上，gas 计量                                 │
└────────────────────┬────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────┐
│                  索引器（Indexer）                        │
│   The Graph / subgraphs                                  │
│   监听事件、构建索引、提供 GraphQL 查询                    │
└─────────────────────────────────────────────────────────┘
```

### 各组件职责

- **前端**：用户交互界面，通过 wagmi 或 ethers.js 与钱包交互。前端不直接连接链上合约——所有状态读取通过索引器（链下），所有状态写入通过钱包签名后提交链上。
- **钱包**：管理私钥、签名交易、提交到链上。钱包是用户与链之间的信任锚——私钥泄漏即资产损失。
- **合约**：链上智能合约，执行应用逻辑。合约代码不可升级（除非使用代理模式），升级需要治理。
- **索引器**：监听链上事件、构建索引、提供 GraphQL 查询。索引器解决了前端直接查询链的延迟问题，但索引器的数据源仍是链上状态。

## 开发栈

### 合约层

- **语言**：Solidity（EVM 链）、Move（Aptos/Sui）
- **测试框架**：Hardhat、Foundry
- **部署**：硬编码部署脚本、通过 CI/CD 自动部署

### 前端层

- **框架**：React + wagmi、Next.js + viem
- **钱包集成**：wagmi（React hooks）、viem（TypeScript）
- **状态管理**：本地状态 + 链上状态通过索引器查询

### 链下索引

- **The Graph**：subgraph 监听链上事件，构建 GraphQL 索引
- **自建索引器**：监听链上事件，存入数据库，提供自定义 API

## 安全事故

### The DAO 事件（2016）

- **损失**：约 3600 万 ETH（当时约 6000 万美元）
- **原因**：重入漏洞（Reentrancy），攻击者在合约状态更新前再次调用外部函数
- **影响**：以太坊硬分叉回滚交易，社区分裂，[DAO](/zh/consensus/DPOS) 治理讨论持续至今
- **出处**：参见[智能合约漏洞攻击](/zh/hacking/SmartContractVulnerabilities)

### Ronin 桥事件（2022）

- **损失**：约 6.2 亿美元
- **原因**：伪造交易签名，通过 Ronin 桥将未铸造的代币发送到以太坊主网
- **归因**：攻击者被关联到朝鲜 Lazarus Group
- **出处**：[BBC·Ronin Network: What a $600m hack says about the state of crypto](https://www.bbc.com/news/technology-60933174)

### 跨链桥攻击（2022）

- **损失**：约 30 亿美元（Ronin 6.2 亿 + Nomad 1.9 亿 + Harmony 1 亿等）
- **原因**：跨链桥的签名验证或权限管理漏洞
- **影响**：跨链桥成为最大攻击面，[信任最小化桥](/zh/hacking/CrossChainBridgeAttack) 成为研究方向
- **出处**：参见[跨链桥攻击](/zh/hacking/CrossChainBridgeAttack)

## L1/L2 选型

| 维度 | L1（以太坊、Solana） | L2（Optimism、Arbitrum、zkSync） |
| --- | --- | --- |
| 最终性 | 秒到分钟 | 分钟到小时（取决于乐观/ZK） |
| Gas 费 | 高 | 低（1-2 个数量级） |
| 安全模型 | 原生 BFT / PoS | 继承 L1 安全 + 有效性证明 |
| 适用场景 | 高价值结算、去中心化金融 | 高频交易、链上游戏 |
| 代表项目 | [Ethereum](/zh/chains/Ethereum)、[Solana](/zh/chains/Solana) | [Optimism](/zh/chains/Optimism)、[Arbitrum](/zh/chains/Arbitrum) |

### Gas 费策略

- **L1 Gas**：直接由用户支付，高波动性
- **L2 Gas**：通过 rollup 压缩提交，低波动性
- **Gasless**：通过支付代付（paymaster）实现零 Gas 体验，适合前端应用

## 典型案例

### Uniswap

- **类型**：去中心化交易所（DEX）
- **架构**：前端（React）+ 钱包（MetaMask）+ 合约（Solidity）+ 索引器（自建）
- **特点**：AMM（自动做市商）模型，池子流动性由用户提供
- **出处**：[Uniswap 文档](https://docs.uniswap.org)

### Aave

- **类型**：去中心化借贷协议
- **架构**：前端 + 钱包 + 合约 + 索引器
- **特点**：超额抵押借贷，风险参数由治理决定
- **出处**：[Aave 文档](https://docs.aave.com)

### ENS

- **类型**：去中心化命名系统
- **架构**：前端 + 钱包 + 合约 + 索引器
- **特点**：链上名字解析，对标传统 DNS
- **出处**：[ENS 文档](https://docs.ens.domains)

## 失败模式

- **钱包即信任锚**：私钥管理是 DApp 安全的最大单点。钱包私钥泄漏或前端漏洞导致资产直接损失。
- **合约不可升级**：大部分智能合约部署后无法修改代码。漏洞只能靠治理升级代理合约或接受损失。
- **Gas 费波动**：L1 Gas 费在高峰期可超过 100 美元，严重影响用户体验。L2 缓解了这一问题，但引入了乐观/ZK 验证延迟。
- **索引器信任**：索引器是前端与链之间的数据源，索引器被攻击或数据错误会导致前端显示错误信息。
- **前后端分离**：前端不信任后端（前端是用户本地运行的代码），但前端需要信任链上状态。这种信任模型的不对称是 DApp 架构的固有张力。
