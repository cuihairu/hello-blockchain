# R3 Corda

Corda 是 R3 联盟（2015 年由金融机构发起）设计的分布式账本平台：它自称「为商业而生」——交易**不全局广播**，只在交易的相关方（stakeholder）之间点对点共享；全局唯一性（防双花）交给独立的**公证人（notary）**基础设施验证。账本模型用 [UTXO](/zh/model/UTXO)（状态 + 契约）而非[账户模型](/zh/model/Account)，业务流程用确定性的 **flow 框架**编排。用 Kotlin 编写、跑在 JVM 上，合约可以用 Java 及其他 JVM 语言写。

Corda 与「区块链」的经典差异就在**没有全局账本**：每个节点只看到与自己相关的交易，隐私是结构性默认而非附加层。

## 四要素

- **在哪一层**：[结算层](/zh/layers/Settlement) —— 状态的唯一性与排序由公证人保证，账本按相关方分区
- **解决什么**：金融机构间协作要「交易只让相关方看见 + 全局防双花」；Corda 用点对点共享 + 公证人签名把这两件事拆开
- **解决得怎么样**：隐私默认（不相关方根本拿不到数据）、公证人可插拔（ validating / non-validating 两种模式）、JVM 生态对金融 IT 友好；代价是「没有全局账本」让全局可观测性变弱、公证人成为需要单独治理的信任锚、跨网络互操作要靠额外层（网络地图与信任根）
- **出处**：[corda/corda 仓库](https://github.com/corda/corda)（官方 README：Features 节列出 flow 框架、点对点网络、notary 基础设施「validate uniqueness and sequencing of transactions without global broadcast」、CorDapps）；官方文档站 docs.r3.com 在本站撰写时不可达（403，未找到公开镜像可替代）

## 核心机制

- **状态与契约（UTXO 系）**：账本的原子单位是「状态（state）」——一份带类型的数据加一个所有者。交易消耗输入状态、产出输出状态；每个状态类型配一个契约（contract），验证「这笔消耗与产出在业务上合法」。这与[比特币的 UTXO](/zh/model/UTXO) 同族，但状态可以承载任意业务数据（票据、协议、头寸）。
- **公证人（notary）**：防双花的组件——交易先送给公证人，公证人确认输入状态未被消费后在交易上签名（提供时间戳与排序）。两种模式：validating notary 重新执行交易验证其合法；non-validating notary 只检查状态未被消费、不看交易内容（隐私更好，但把信任更多交给交易发起方）。公证人是独立的信任锚，可由多机构组成集群。
- **点对点共享（无全局广播）**：交易只发给它的相关方（输入状态的拥有者、输出状态的参与人、公证人）。没有全局内存池、没有全网区块广播——「账本」是每个节点各自持有的交易子图。
- **flow 框架**：业务流程（发起、协商、签名收集、公证、落账）写成确定性 flow——一个跨多轮消息交换的状态机，JVM 运行时负责挂起恢复、错误重试。CorDapp（Corda 应用）= 合约 + flow + 状态的打包。
- **两代架构**：仓库里的第一代实现覆盖 Corda 1-4；Corda 5 起换成第二代架构（应用与集群解耦的重组，官方 README 标注二代实现移至别处）。
- **网络与准入**：节点身份由网络地图（network map）服务管理，准入靠会员策略——Corda Network 是其全球网络，业务网络（BN）可在其上自建治理。

## 与其他联盟链的差异

| 维度 | Corda | [Fabric](/zh/consortium/Fabric) | [FISCO BCOS](/zh/consortium/FiscoBcos) | [Besu](/zh/consortium/Besu) |
| --- | --- | --- | --- | --- |
| 数据可见性 | 点对点，无全局账本 | 通道（组织子集一个账本） | 群组（节点子集一个账本） | 链全局可见 + 隐私交易可选 |
| 防双花/排序 | 公证人签名 | 排序服务（Raft） | 群组内 PBFT | QBFT 投票 |
| 账本模型 | UTXO（状态+契约） | KVDB 世界状态 | 群组内共享账本 | 账户模型（EVM） |
| 合约语言 | Java / JVM 系 | Go / Java | Solidity / Go / Java | Solidity |
| 实现语言 | Kotlin / JVM | Go | C++ | Java |

## 失败模式

- **公证人信任锚**：non-validating 模式下公证人只保唯一性不验内容——发起方提交非法交易时防线在接收方的本地验证；validating 模式则让公证人看到交易内容，隐私收窄。模式选择本身就是权衡。
- **全局可观测性弱**：没有全局账本意味着监管审计、全网风控需要额外的数据上报层（交易各方各自导出），跨机构对账依赖相关方诚实执行协议。
- **网络地图单点**：网络地图与身份服务故障会影响新连接建立与成员准入，运维上需要多实例部署。
- **版本迁移成本**：Corda 1-4 与 Corda 5 是两代架构，迁移不是平滑升级（官方 README 明示两代实现分仓）。
- **主网级重大事故**：未找到公开记录。
