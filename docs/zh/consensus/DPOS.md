# DPoS

委托权益证明（Delegated Proof of Stake, DPoS）是 PoS 的代议制变体：全体持币人不直接出块，而是投票选出固定数量（通常 21~101 个）的"代表/超级节点"，由这些代表轮流、高效地生产区块。

## 四要素

- **在哪一层**：[结算层](/zh/layers/Settlement) —— 代议制：21~101 个代表轮流生产区块，出块权由投票决定
- **解决什么**：兼顾吞吐与问责——让少量代表出块换取高 TPS 与快确认，持币人保留投票权并可撤换代表
- **解决得怎么样**：吞吐与出块速度显著高于 PoW/PoS；代价是代表高度集中（EOS 21 个 BP）、互投联盟与选票交易难防、低投票率下治理攻击几乎无法用技术手段阻止
- **出处**：Daniel Larimer，BitShares 白皮书 2014

## 基本原理

1. **投票选出代表**：持币人按持币量加权投票（或抵押投票），得票前 N 名成为出块节点。
2. **轮流出块**：代表按预定顺序（轮转或随机洗牌）出块，出块间隔通常在秒级（EOS 0.5 秒、BTS 约 2 秒）。
3. **持续问责**：不出块、频繁掉线的代表会被跳过；声誉恶化会被投票换掉。

## 特点

**优点**

- **吞吐量高**：验证人少、通信复杂度低，区块时间短，适合高 TPS 应用。
- **确认快**：EOS 采用 BFT 式确认（Irreversibility），交易数秒内不可逆。
- **治理闭环**：代表身份公开，作恶直接承受声誉与被投出去的代价；EOS 曾以宪法/仲裁机制处理争议。

**缺点**

- **去中心化程度受限**：少数验证人易形成卡特尔、互投联盟，投票率低时"富者愈富"更明显。
- **治理攻击**：选票交易（bribing）与交易所代持投票难以防范。

## 代表应用

- **EOS**：21 个超级节点（Block Producer），DPoS + BFT 最终性。
- **BitShares**：Daniel Larimer 最初提出的 DPoS 实现。
- **TRON**：27 个超级代表（Super Representative）。
- **Lisk、Ark** 等也采用 DPoS 变体。

## 落地样本：Livepeer

> 来源：meshio research（2026-10-13 合并），细节对照 docs.livepeer.org 与 Livepeer 白皮书/规范。

Livepeer 把 DPoS 组装成转码服务网络，三个机制是通用教科书：

- **概率验证**：不对每段视频验证，按 `Sha3(N, BlockHash, Seg#) % VerificationRate == 0` 抽样（白皮书示例 1/500）触发检查，验证失败或漏验 slash 质押（5% / 10%）——把作弊期望收益做成负数，同时压低链上验证成本（mainnet 目前罚没未启用）。
- **概率微支付票据**：broadcaster 每段发一张签名票据（面值 × 中奖概率 = 段价），只有中奖票据上链兑付 ETH——链下高频、链上低频的结算形态。
- **双旋钮分成**：orchestrator 用 `rewardCut`（自留通胀比例）与 `feeShare`（ETH 费用分给委托人比例）显式定价，通胀奖励按质押比例分池、每轮须主动调用 `reward()` 领取（漏调即放弃）——动态通胀按质押率向目标值调节。
