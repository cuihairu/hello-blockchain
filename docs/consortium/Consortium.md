# 联盟链

联盟链（consortium blockchain / permissioned blockchain）是「节点由已知成员治理、准入需要授权」的区块链：它保留分布式账本与共识，但把「谁能进来记账」变成治理问题而非博弈问题——成员数量有限且身份可查，共识从「抗任意作恶者」退化为「容忍 f 个成员作恶」，于是可以用 BFT 投票（[PBFT](/consensus/PBFT)、[QBFT](/consensus/QBFT)、[MaxBFT](/consensus/MaxBFT)）换高吞吐与确定性最终性，代价是失去无许可开放性与外部匿名性。

本目录按「项目 → 四要素 → 机制 → 失败模式」写联盟链。四要素区块的「在哪一层」统一归[结算层](/layers/Settlement)：共识算法决定的是状态怎么落定，联盟链只是把「谁有资格投票」改成了治理问题。与公链的设计对照见[联盟链与公链对照表](#联盟链与公链对照表)。

## 读法

- 先读[对照表](#联盟链与公链对照表)定位「联盟链 vs 公链」的轴，再进单个项目页看机制与失败模式。
- 联盟链的核心张力是「治理换性能」：节点数从数百万降到几十个，可以跑 2/3 多数投票，但安全边界从「算力/质押经济」变成「成员名单的法律约束」。
- 「失败模式」一节给真实风险与事故（有的项目未找到公开记录，如实标注）。
- 术语与卡片的平铺查询在[术语表](/cards/Glossary)与[知识卡片索引](/cards/Cards)。

## 联盟链与公链对照表

| 维度 | 公链（Bitcoin / Ethereum） | 联盟链（Fabric / FISCO BCOS / Corda / Besu） |
| --- | --- | --- |
| 准入 | 无许可，任何人都可运行节点 | 许可制，节点由已知成员治理 |
| 身份 | 匿名地址，抗女巫靠资源（算力/质押） | 实名或准实名，身份可查可追责 |
| 共识 | [PoW](/consensus/POW)、[PoS](/consensus/POS) 等无许可共识 | [PBFT](/consensus/PBFT)、[QBFT](/consensus/QBFT) 等 BFT 投票 |
| 容错模型 | 异步网络 + 拜占庭容错，安全边界是经济成本 | 部分同步 + 拜占庭容错，安全边界是成员名单（n ≥ 3f+1） |
| 最终性 | 概率最终性（确认数越多回滚越难）或最终性 gadget | 确定性最终性（投票达阈即不可逆） |
| 吞吐 | 个位数到千级 TPS | 数十到数千 TPS（节点数少，网络往返短） |
| 隐私 | 公开账本，隐私靠层（[零知识证明](/Privacy/ZeroKnowledgeProof)、[混币](/Privacy/MixingServices)） | 账本本身按成员/通道分区，业务数据天然隔离 |
| 治理 | 社区治理，无中央实体 | 成员约定，常为财团或行业联盟 |
| 费用 | gas / 手续费 | 通常无链上交易费（成员间结算） |
| 典型场景 | 公共货币、开放金融 | 跨机构协作、供应链金融、监管合规场景 |

## 失败模式

- **成员集中**：联盟链的安全边界是成员名单。若少数成员合谋作恶超过容错阈值（f < n/3），协议无法防御；名单本身也是单点——治理失败即协议失败。
- **身份与隐私的矛盾**：实名身份支持追责，但也让业务数据可被成员关联。Fabric 用[通道](/consortium/Fabric)隔离、Corda 用[不公开账本](/consortium/Corda)缓解，但都依赖成员遵守协议。
- **治理僵化**：成员退出、新增或升级需要共识与法律安排，升级成本高。
- **性能与去中心化的权衡**：吞吐随节点数下降而提升——加节点会降性能，而加节点又是去中心化的要求。
