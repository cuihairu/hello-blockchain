# WeBASE

WeBASE（WeBank Blockchain Application Software Extension）是微众银行开源的区块链中间件平台，部署在[FISCO BCOS](/consortium/FiscoBcos)与业务系统之间：把「连节点、发交易、管合约、管私钥、查数据」这些区块链的原始操作封装成 Web 管理平台与 REST 接口，让不熟悉区块链细节的业务开发者像调普通后端服务一样用链。

它的定位对应公链世界的「节点服务商 + 区块浏览器 + 合约 IDE + 钱包后台」的组合，但服务于许可链场景——没有开放钱包，私钥管理由链运营方托管。

## 四要素

- **在哪一层**：[服务发现](/layers/ServiceDiscovery)与[计算层](/layers/Compute)之间的接入面 —— 中间件不参与共识，负责把业务请求转成链上交易、把链上事件转成业务可查数据
- **解决什么**：联盟链的节点接口是底层 RPC，业务系统直连需要自己处理签名、群组路由、证书、数据导出；WeBASE 把这些横切能力集中成中间件层
- **解决得怎么样**：提供节点前置（代理连接）、节点管理（聚合 API 与运维）、Web 管理台（合约 IDE、私钥托管、数据概览、交易审计）、独立签名服务（私钥隔离）与数据导出（链上数据入数据库）；代价是多一层部署与运维、托管私钥成为集中攻击面、平台本身与 FISCO BCOS 生态绑定
- **出处**：[WeBASE 技术文档](https://webase-web.readthedocs.io/en/latest/)（官方文档列明 WeBASE-Front、WeBASE-Node-Manager、WeBASE-Web、WeBASE-Codegen-Monkey、WeBASE-Collect-Bee、WeBASE-Sign、WeBASE-Transaction 各子系统）

## 核心机制

- **WeBASE-Front（节点前置）**：部署在节点本机或同网段的代理服务，封装节点 RPC，提供交易签名与发送、合约调用、区块与事件查询的 REST 接口。它是管理平台与链之间的必经网关。
- **WeBASE-Node-Manager（节点管理）**：聚合多个 Front，统一管理节点、群组、用户与合约；对外提供统一的业务 API，对内做权限与审计。管理台（WeBASE-Web）的后端就是它。
- **WeBASE-Web（管理平台）**：浏览器端管理台。官方文档列出的模块：区块链数据概览、节点管理、合约管理（在线 IDE 编译部署）、私钥管理、系统监控、交易审计、账号管理。
- **WeBASE-Sign（签名服务）**：独立部署的签名服务，私钥不落业务系统——业务方把待签数据发给 Sign 服务，由它用托管密钥签名后返回。私钥与应用系统隔离，降低密钥泄漏面。
- **WeBASE-Transaction（交易服务）**：交易编排服务，处理并发交易的场景化签名与发送，把「组装交易→签名→发送→拿回执」封装成一步调用。
- **WeBASE-Codegen-Monkey（代码生成）**：从合约 ABI 生成 Java 代码与数据模型，让 Java 业务工程直接以对象方式调用合约。
- **WeBASE-Collect-Bee（数据导出）**：把链上区块、交易、事件导出到关系数据库——联盟链的审计与报表通常在数据库侧完成，而不是直接查链。

## 失败模式

- **托管私钥的集中风险**：WeBASE-Sign 与管理台的私钥托管把「每人一把钥匙」变成「平台代管一批钥匙」——平台被攻破即批量密钥泄漏。生产部署必须把 Sign 服务独立组网、最小权限访问。
- **中间件成为单点**：业务流量都过 Front/Manager，它们故障即业务不可用；链本身还在，但接入层需要高可用部署。
- **审计依赖导出完整性**：交易审计与报表基于 Collect-Bee 导出的数据库副本，导出管道断点或配置遗漏会让「数据库视图」与「链上事实」脱节——以链为准的核对机制不可省。
- **生态绑定**：WeBASE 面向 FISCO BCOS 系节点，跨链型联盟（Fabric/Besu 混合部署）无法复用，接入层选型要与链选型绑定评估。
- **重大安全事故**：未找到公开记录。
