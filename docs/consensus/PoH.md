# PoH

Proof of History (PoH) is the signature component of Solana: a **continuously running verifiable delay hash sequence** that provides a verifiable global clock for all events on the network, ahead of consensus. Strictly speaking PoH is not consensus, but the "time layer" that works together with [TowerBFT](/consensus/TowerBFT).

## Four Key Points

- **Which layer**: the **time layer** above the settlement layer — strictly speaking not consensus, but the global clock that pairs with [TowerBFT](/consensus/TowerBFT)
- **What it solves**: Provide a verifiable global clock for all network events that precedes consensus — use a continuously running delay hash sequence to order events, so nodes never have to negotiate "this happened before that"
- **How well it works**: Ordering communication overhead drops dramatically, supporting Solana's high throughput and short block times; the cost is that the sequence is generated by a single leader, verifiability does not mean the generator can be trusted, and resistance to grinding depends on additional draw and slashing design
- **Sources**: Anatoly Yakovenko "Solana: A new architecture for a high performance blockchain" 2017

## Basic Principles

The sequence iterates indefinitely as $h_{n+1} = \text{hash}(h_n)$. Key properties:

- **Seriality**: $h_n$ depends on the previous value and cannot be computed ahead in parallel, so the $n$-th hash really happened after the $n-1$-th.
- **Events can be inserted**: transaction hashes are "slipped" into the sequence (continue iterating after `hash(h_n, tx)`), which proves the transaction **already existed before this moment**.
- **Verifiable**: a verifier can recompute any fragment in parallel (as long as it holds the starting value in advance), so verification is far faster than generation.

## Role in Solana

1. **Leader ordering**: the current leader (the producer for 4 consecutive slots drawn by stake) embeds transactions into the PoH flow; the transaction order is fixed before broadcast, so validators never need to vote on ordering.
2. **Slot-based time**: one slot is about 400 ms, and a hashing frequency on the order of 1.6 million TPS slices time into fine grains; combined with Turbine (sharded propagation) and Gulf Stream (memory-pool-free forwarding) this delivers high throughput.
3. **Reduced consensus load**: TowerBFT only needs to vote on "block hashes at PoH heights" (see [TowerBFT](/consensus/TowerBFT)); messages are small and rounds are few.

## Controversy and Boundaries

- **Not a sybil resistance mechanism**: the right to produce still comes from staking (leader election); PoH only provides ordering.
- **Single leader dependency**: when the leader goes down the PoH flow breaks, and a new leader must be switched in to continue the chain; historically several outages trace back to this and to client defects.
- **Decentralization criticism**: the hardware barrier to high throughput (many cores + large memory + high bandwidth) concentrates validators, which is an evaluation axis independent of "clock neutrality".
