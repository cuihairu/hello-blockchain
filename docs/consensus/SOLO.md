# SOLO

SOLO 是"单节点共识"的直译式命名，指由**单一节点独立出块并确认**的共识模式：没有投票、没有分叉处理，所有区块由该节点顺序产生。它不是抗拜占庭协议，而是开发、测试与极端中心化场景的工程选择。

## 特点

- **零通信开销**：出块时延只受本地 IO 限制，可轻松数千 TPS，区块即时"最终"（因为唯一的记账人说了算）。
- **实现极简**：无 leader 选举、无签名聚合、无视图切换；共识模块退化为"顺序写账本"。
- **安全性完全取决于该节点**：节点作恶或宕机，账本即失真或停摆——没有任何冗余。

## 使用场景

1. **开发与单元测试**：长安链（ChainMaker）、Hyperledger Fabric 的 solo/开发模式、Tendermint 的 kvstore demo 等都提供 solo 共识，用于本地功能验证。
2. **私有链 PoC**：企业内部单机构记账试点，之后再升级为 RAFT 或 PBFT。
3. **索引/审计链**：只需防篡改哈希链、不需要多方互信的场景（如本地取证存证）。

## 与 RAFT 的边界

SOLO 无副本、无故障转移；当需要"高可用但无需拜占庭容错"时，下一步是 [RAFT](/consensus/RAFT)（多副本、崩溃容错）；当参与方互不信任时，才是 PBFT/Tendermint 类 BFT 共识（见 [BFT](/consensus/BFT)）。
