# SPoS

SPoS（Secure Proof of Stake，安全权益证明）是 Elrond（2022 年更名 MultiversX）的共识算法：**随机抽样 + 随机轮换的共识组 + 组内 BFT 投票**。它要解决的问题很具体：在分片架构里，每个分片内部也要有一个能投票的小共识组——随机抽样让这个组既小（几十个节点）又不可预知（每轮重抽）。

## 四要素

- **在哪一层**：[结算层](/layers/Settlement) —— 分片内共识：随机抽样共识组 + 组内 BFT
- **解决什么**：分片链的悖论——分片要小才快，但小组易被攻占；SPoS 用「每轮随机抽样共识组 + 随机轮换」让小组成员不可预知，攻击者无法提前埋伏
- **解决得怎么样**：吞吐随分片数近线性扩展，出块秒级；代价是跨片交易要异步处理（复杂度高）、随机信标的可验证性是安全根基、验证人生态集中度偏高
- **出处**：Elrond 白皮书 2019（Adrien Dubois 等）；MultiversX 文档

## 核心机制

- **共识组抽样**：每个分片每轮从验证人池里随机抽几十个节点组成共识组，组内再做 BFT 投票（2/3 阈值）。
- **随机信标（randomness beacon）**：抽样与轮换的随机性来自前一轮共识的聚合签名（BLS 阈值签名），不可预知也不可操纵。
- **分片内 + 分片间**：每个分片独立出块与投票；跨片交易走异步中继，最终由元链（metachain）协调。
- **质押与罚没**：验证人质押 EGLD，作恶可被罚没；质押可委托。

## 与同族协议的差异

| 协议 | 关系 | 关键差异 |
| --- | --- | --- |
| [Tendermint](/consensus/Tendermint) | 同类（BFT 投票） | Tendermint 全网验证人投票，SPoS 在分片内小投票组投票 |
| [Ouroboros](/consensus/Ouroboros) | 同类（随机选主） | Ouroboros 抽签选 slot leader，SPoS 抽样整个共识组 |
| [Algorand](/consensus/Algorand) | 同类（随机抽样） | Algorand 的抽样面向全网，SPoS 的抽样面向每个分片 |
| [Gasper](/consensus/Gasper) | 对比 | Gasper 是单链最终性 gadget，SPoS 的最终性在各分片内独立达成 |

## 失败模式

- **随机信标是单点假设**：BLS 聚合签名的随机性如果被预测或操纵，抽样组就可被提前埋伏——整条安全链坍塌。
- **跨片异步复杂度**：跨分片交易走异步中继，一致性语义（原子性）要应用层自己兜，开发负担高于单链。
- **共识组小 = 攻击面集中**：几十个节点的组被攻占（密钥泄露、合谋）就足以让一个分片作恶，罚没是唯一威慑。
- **生态集中**：验证人与质押池集中度偏高，去中心化更多靠质押分布而非准入协议保证。

SPoS 是「分片 + BFT」这条路线里最完整的工程样本：**用随机抽样解决「小组不可信」的悖论**。它的成败也标定了分片共识的难度——技术问题都解了，跨片开发的生态门槛才是真正的护城河。
