# Gasper

Gasper 是以太坊主网在 The Merge（2022-09）之后的共识算法，由两条独立机制组合而成：**LMD-GHOST**（出块时的分叉选择）与 **Casper FFG**（最终性投票）。它把「选哪条链」和「哪条链不可逆」拆成两个独立组件，是模块化共识设计的代表。

## 四要素

- **在哪一层**：[结算层](/layers/Settlement) —— 以太坊主网共识：LMD-GHOST 选头、Casper FFG 定案，二者分工
- **解决什么**：把 PoW 时代的概率最终性过渡到 PoS，同时保留分叉选择与最终性两条线——GHOST 选头、FFG 定案，让既有应用平滑迁移
- **解决得怎么样**：Merge 后运行至今，能耗下降约 99.95%，确认更快；代价是弱主观性（新节点必须从近期可信状态同步）、罚没机制有边缘情况（inactivity leak）、分叉选择与最终性规则复杂
- **出处**：Buterin、Griffith《Casper the Friendly Finality Gadget》2017；LMD-GHOST 规范；以太坊共识规范（Gasper）

## 两条机制各管一件事

- **LMD-GHOST（Latest Message Driven GHOST）**：出块时选哪条链。每个验证人按自己最近一次投票的权重累加，选累计权重最大的子树。它解决的是「分叉时选哪条」，不解决「哪条不可逆」。
- **Casper FFG（Friendly Finality Gadget）**：最终性投票。验证人对「检查点」投票，一个检查点获得 2/3 质押权重投票即被「合理化」（justified），再获得下一轮 2/3 投票即被「最终化」（finalized）。它解决的是「哪条不可逆」。

## 关键概念

- **检查点（checkpoint）**：每个 epoch 的边界块。FFG 不对每个块投票，只对检查点投票，降低投票开销。
- **合理化（justified）与最终化（finalized）**：一个检查点被 2/3 质押投票合理化；它的子检查点再被 2/3 投票，父检查点就最终化。最终化即不可逆。
- **弱主观性（weak subjectivity）**：新节点从创世同步时，无法从链本身判断哪条是「真链」——必须从近期可信状态（检查点）起步。这是 PoS 逃不掉的代价。
- **罚没（slashing）**：双签与环绕投票被证据化惩罚，是 PoS 的经济安全核心。
- **inactivity leak**：当链长时间无法最终化（如 1/3 以上验证人离线），未投票的验证人会被缓慢罚没，直到剩余验证人重新达到 2/3。

## 与 PoW 时代的对比

| 维度 | PoW（中本聪共识） | Gasper（PoS） |
| --- | --- | --- |
| 出块权 | 算力竞争 | 质押加权随机选人 |
| 分叉选择 | 最长链（累计难度） | LMD-GHOST（累计投票权重） |
| 最终性 | 概率（确认数越多越难回滚） | 确定性（2/3 投票即不可逆） |
| 能耗 | 高 | 低约 99.95% |
| 新节点同步 | 从创世即可验证 | 需弱主观性（近期可信状态） |

## 失败模式

- **罚没边缘情况**：双签证据的判定、环绕投票的界定都有边界，误罚会打击诚实验证人。
- **inactivity leak 的副作用**：大规模离线事件（如客户端 bug）会触发连锁罚没，曾导致部分验证人被误伤。
- **分叉选择攻击**：LMD-GHOST 的权重累加对「投票历史」敏感，验证人若被诱导在错误分支投票，会放大分叉。
- **最终性延迟**：网络分区或验证人离线时，最终化会停摆——链还在出块，但检查点不再被最终化。

Gasper 的设计哲学是**把最终性从出块里拆出来**：出块可以慢、可以分叉，但最终性由独立的投票层保证。这个拆分让以太坊能在不重写执行层的前提下完成 PoW→PoS 过渡。
