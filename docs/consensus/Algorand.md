# Algorand

Algorand 是 Silvio Micali（2012 年图灵奖得主）2017 年提出、2019 年上主网的「纯 PoS」共识，核心创新是把出块权分配做成**秘密可验证随机（VRF）抽签**，被抽中之前没有人知道候选人是谁，从而规避「针对性攻击」。它由两个协议组成：**BA\***（选主）与 **BA\*-VRF**（投票）。

## 四要素

- **在哪一层**：[结算层](/layers/Settlement) —— 纯 PoS，VRF 抽签选主 + 投票确认，无许可、无投票轮
- **解决什么**：让出块权在抽签揭示前不可预知——候选人选不出就无法被针对性攻击（无法预谋拒绝服务、无法提前埋伏），把抗女巫从「资源对抗」变成「随机选择」
- **解决得怎么样**：无许可、出块快（约 4-5 秒）、无需传统 BFT 的多轮投票；代价是安全性依赖 VRF 正确性、最终性是概率性的、网络参数（抽样大小 k）对安全边界敏感。公开事故：未找到公开记录
- **出处**：Silvio Micali《Algorand: A Secure Decentralized Ledger》2017；Micali 关于 Algorand 的系列论文 2017-2019

## 核心机制

- **BA\*（Byzantine Agreement Star）**：主协议。每个周期抽一个候选人，候选人生成区块并广播；其他节点用 BA\*-VRF 投票，多数同意后区块被确认。
- **BA\*-VRF（投票协议）**：子协议。被抽中的投票人用 VRF 决定是否投票，投票结果不可被预知。
- **秘密可验证随机**：VRF 的关键性质是「秘密性」——抽签结果在被计算出来之前，候选人和攻击者都无法预知。攻击者无法针对性地让候选人不上线。
- **无投票轮（voteless）**：Algorand 不需要传统 BFT 的「轮次」——出块即投票，投票即出块，一轮完成。

## 与同族协议的差异

| 协议 | 关系 | 关键差异 |
| --- | --- | --- |
| [Ouroboros](/consensus/Ouroboros) | 同类（VRF 选主） | Ouroboros 出块与最终性在同一套规则里；Algorand 把出块和投票做成两个独立的 BA\* 协议 |
| [BABE](/consensus/BABE) | 同类（VRF 选主） | BABE 出块、GRANDPA 定案分离；Algorand 出块与投票在 BA\* 框架内完成 |
| [Avalanche](/consensus/Avalanche) | 同类（概率共识） | Avalanche 用亚采样投票，Algorand 用 VRF 抽签 + BA\* 投票 |
| [TowerBFT](/consensus/TowerBFT) | 并行路线 | TowerBFT 靠 PoH 时序确定 leader，Algorand 靠 VRF 随机 |

## 失败模式

- **VRF 正确性是门票**：秘密可验证随机性一旦可被预测，Algorand 的安全性直接失效。
- **抽样大小 k 的边界**：BA\* 的安全性证明依赖抽样大小 k 达到某个阈值，k 过小则攻击成本降低。
- **概率最终性**：Algorand 的最终性是概率性的，需要多个确认才能达到足够低的回滚概率。
- **候选人拒绝服务**：候选人在出块前可被拒绝服务（如网络攻击），导致周期无块。Algorand 对此有重试机制，但会延迟。

Algorand 的贡献是**把「谁来出块」变成真正秘密的随机事件**，让「针对性攻击」在协议层面被排除——你甚至不知道谁会出块，所以无法针对性地让它不出块。
