# 交易拒绝服务攻击

交易拒绝服务攻击（Transaction DoS Attack）是指攻击者向区块链网络注入大量无效、低价值或恶意构造的交易，消耗节点的计算、内存与带宽资源，挤占正常交易的打包空间，从而拖慢甚至瘫痪网络确认能力的攻击方式。

## 攻击原理与方法

1. **垃圾交易洪泛**：
   - 攻击者批量发送大量合法签名但无实际意义的交易，每笔手续费极低。
   - 区块的容量（比特币约 1 MB 区块 + 见证数据，以太坊按 Gas 上限）是稀缺资源，垃圾交易会与正常交易竞争打包位置，抬高全网手续费。

2. **无效交易消耗验证资源**：
   - 构造签名校验昂贵或脚本复杂的交易：验证成本由全网节点承担，而打包失败的交易仍会占用内存池校验时间。
   - 例如早期比特币网络曾出现过利用 `OP_CHECKMULTISIG` 等昂贵脚本构造的低费交易对节点造成压力。

3. **内存池膨胀**：
   - 大量从未被打包的低费交易长期占据节点内存池（mempool），使节点内存耗尽、同步变慢。
   - 内存池不同步还会放大网络分裂风险：不同节点看到不同的"待确认交易集合"。

4. **重放与重复广播**：
   - 同一笔交易被反复广播，或在不同链（分叉链）上重放，浪费节点处理与转发带宽。

## 典型影响

- **确认延迟**：正常交易被迫提高手续费才能在合理时间内被打包。
- **全网手续费上涨**：2017 年底比特币网络拥堵、2021 年某 NFT 铸造热潮导致 Ethereum Gas 飙升，都是"交易洪泛挤占容量"的现实形态。
- **节点掉线**：资源不足的家用节点可能因内存池膨胀而崩溃或被逐出网络，降低去中心化程度。
- **次生攻击**：拥堵窗口常被用来放大双花、抢跑等攻击的成功率。

## 防御措施

1. **手续费市场与最低转发费**：节点只转发手续费高于阈值（如比特币的 `minrelaytxfee`）的交易，让垃圾交易"贵到不划算"。
2. **内存池与速率限制**：限制单节点内存池大小、对单一对等节点的交易广播做速率限制，及时淘汰低费老旧交易。
3. **验证成本定价**：共识层按资源消耗计费（以太坊 Gas 按计算、存储、内存多维定价），把验证成本转嫁给交易发起者。
4. **交易池策略与 pruning**：节点可配置更严格的交易接受策略（拒绝非标准脚本），并对长期未确认交易做清理。
5. **监控与告警**：对内存池水位、交易费率、节点延迟建立监控，异常洪泛时调整中继策略。
